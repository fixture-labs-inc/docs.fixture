This guide gets you from zero to a working connection. The fastest path is
**Claude Desktop** using the `mcp-remote` bridge, which handles the OAuth sign-in
for you.

## Prerequisites

- A **FixtureLabs account** (you sign in with Google).
- An MCP-capable client. This guide uses [Claude Desktop](https://claude.ai/download).
- [Node.js 18+](https://nodejs.org) — `mcp-remote` runs through `npx`.

<Note>
The server is **remote**. You don't clone or run anything from FixtureLabs — you
only point your client at the endpoint below.
</Note>

## 1. Confirm the server is reachable

Before signing in, hit the public discovery endpoint. No auth required:

```bash
curl https://app.fixturelabs.io/.well-known/oauth-protected-resource
```

You'll get back JSON describing the resource and its authorization server. If you
see that, the server is up and your client will be able to discover how to log in.

## 2. Add the server to Claude Desktop

Open your `claude_desktop_config.json`:

- **macOS** — `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows** — `%APPDATA%\Claude\claude_desktop_config.json`

Add the FixtureLabs server:

```json claude_desktop_config.json
{
  "mcpServers": {
    "fixturelabs": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://app.fixturelabs.io/api/mcps/mcp"]
    }
  }
}
```

Restart Claude Desktop.

## 3. Sign in

The first time the connection starts, `mcp-remote` opens your browser to the
FixtureLabs consent screen.

<Steps>
  <Step title="Sign in with Google">
    If you're not already logged in to FixtureLabs, you'll be sent to Google
    sign-in and back.
  </Step>
  <Step title="Review the request">
    You'll see which application is asking for access and what it can do, then
    choose **Authorize** or **Deny**.
  </Step>
  <Step title="Done">
    On approval you're redirected back, your client stores the token, and the
    tools become available. You won't be asked again until the token expires and
    can't be refreshed.
  </Step>
</Steps>

<Tip>
`mcp-remote` caches your tokens under `~/.mcp-auth`. If a connection gets stuck,
delete that folder to force a fresh sign-in.
</Tip>

## 4. Call your first tool

Ask Claude something that maps to a tool. For example:

> "Use the fixturelabs **ping** tool with the message *hello*."

You should get back `pong: hello`. Every tool — including `ping` — runs behind the
authenticated endpoint, so this only works once you've signed in. `ping` is the
quickest way to confirm the wiring because it needs no special permissions.

Then try one that reads your account:

> "Call **whoami** on fixturelabs and tell me which account I'm connected as."

This returns the user id, email, role, and granted scopes for your token.

## 5. Do something useful

A few prompts to try once you're connected:

- *"Get me a random unsolved **CAD** question from FixtureLabs to practice."*
- *"List the 5 most recent FixtureLabs blog posts."*
- *"Read the FixtureLabs blog post with slug `getting-started-with-cad`."*
